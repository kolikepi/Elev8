====================================================

CORE OBJECTIVE

An accepted quotation must NOT become permanently locked.

The administrator must be able to revise an accepted quotation when:

* price changes
* carrier changes
* service changes
* transit time changes
* shipment data changes
* weight or dimensions change
* surcharges change
* customs or DG conditions change
* carrier availability changes
* an operational correction is required

However:

NEVER overwrite the previously accepted quotation.

Create a new quotation version.

====================================================

QUOTATION VERSIONING

Introduce quotation versions.

Example:

FWD-2026-00015

Version 1
Price: EUR 320
Status: Accepted

Version 2
Price: EUR 355
Status: Rejected

Version 3
Price: EUR 340
Status: Accepted

Keep the same ForwardOne quotation reference.

Each version must have its own:

* version number
* carrier
* service
* transit time
* carrier cost
* surcharges
* selling price
* currency
* validity
* customer-facing notes
* internal notes
* created timestamp
* created by
* sent timestamp
* accepted timestamp
* rejected timestamp
* status
* revision reason

Never delete old versions.

====================================================

ADMIN — REVISE QUOTATION

For quotations that are:

* SENT
* ACCEPTED
* REAPPROVAL_REQUIRED

allow the administrator to select:

“Revise Quotation”

Do NOT allow silent editing of the currently accepted version.

When the administrator clicks Revise Quotation:

1. Create a new draft version based on the latest version.
2. Pre-fill all existing quotation information.
3. Allow the administrator to modify:

* final carrier
* final service
* transit time
* carrier cost
* fuel surcharge
* remote-area surcharge
* DG surcharge
* insurance
* pickup fee
* delivery fee
* documentation fee
* customs fee
* other charges
* markup
* discount
* VAT
* final selling price
* quote validity
* included services
* excluded services
* customer notes

4. Require a revision reason.

Examples:

* Weight changed
* Dimensions changed
* Carrier rate updated
* Different service selected
* Remote area surcharge added
* Customer requested amendment
* Operational correction
* Other

====================================================

RECALCULATION

Reuse the existing:

* tariff engine
* pricing engine
* carrier-specific volumetric rules
* recommendation engine
* surcharge engine

Do not create parallel calculation logic.

When pricing-relevant shipment data has changed:

* recalculate volumetric weight
* recalculate chargeable weight
* recalculate applicable tariff
* recalculate applicable surcharges
* show previous vs revised calculation

Never invent a rate if no valid tariff exists.

Use:

Manual Rate Required

when necessary.

====================================================

SEND REVISED QUOTATION

After administrator review, provide:

“Send Revised Quotation”

When sent:

* the previous accepted quotation version remains preserved
* the new version becomes the current customer-facing version
* needsReapproval = true
* booking remains blocked
* customer receives an “Updated quotation — action required” notification

Customer-friendly message example:

“Your shipment quotation has been updated. Please review the new offer before we continue with the booking.”

Do not expose internal reasons, carrier costs or margins.

====================================================

CUSTOMER REAPPROVAL

The customer should see the revised quotation clearly.

Show:

* Version number
* Service
* Transit time
* Final price
* Currency
* Validity
* Included services
* Excluded services
* Customer-facing notes

If useful, show a simple customer-safe summary of what changed.

Example:

Previous price:
EUR 320

Updated price:
EUR 355

Do NOT expose:

* carrier cost
* margin
* markup
* internal tariff
* internal admin notes
* internal override reason
* recommendation score

Provide:

Accept Updated Quote

Reject Updated Quote

====================================================

ACCEPT UPDATED QUOTE

When the customer accepts the revised version:

* mark that version ACCEPTED
* record accepted timestamp
* clear needsReapproval
* mark it as the active accepted quotation version
* allow the Booking Details / Booking Checklist workflow to continue
* ensure the booking uses ONLY the latest accepted version

Do not modify the historical status of older versions.

====================================================

REJECT UPDATED QUOTE

When the customer rejects the revised quotation:

* mark the revised version REJECTED
* preserve previous versions
* booking remains blocked
* administrator is notified

The administrator may then:

* create another revision
* cancel the request
* discuss the quote with the customer

====================================================

BOOKING INTEGRATION

The Booking workflow must always reference:

LATEST ACCEPTED QUOTATION VERSION

Booking must be blocked when:

* latest revision is awaiting customer approval
* needsReapproval = true
* latest version is rejected
* no quotation version is currently accepted

Reuse the existing Booking Checklist and Phase A booking workflow.

Do NOT create a second booking system.

====================================================

QUOTE VALIDITY

Each quotation version must support:

Valid Until

If an active quotation expires:

Customer must not be allowed to accept it normally.

Display:

“This quotation has expired.”

Provide:

Request Updated Quote

Administrator can:

* extend validity by creating a revision
    or
* create a newly calculated quotation version

Do not silently change the validity of an already sent quotation.
